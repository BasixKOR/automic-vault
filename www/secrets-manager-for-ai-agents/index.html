Agent-specific secrets management

Secrets manager for AI agents

Automic Vault keeps credentials where agents cannot read them directly. Tools can still receive approved secrets at execution time, but the model does not get a copy to leak, paste, log, or misuse.

Different threat model

Secrets managers were not built for autonomous tool use.

Classic secrets management assumes a human, service, or CI job asks for a value. AI coding agents add a new risk: the system with filesystem and shell access is also reading context and generating commands.

Plaintext files

Remove readable credentials

Move sensitive values out of project files, shell startup files, and tool config that any local process can inspect.

Approved tools

Give tools access, not models

Inject named keys only into the executable that actually needs them, after the approval path is clear.

Local boundary

Use the Mac keychain

Store secrets behind local keychain-backed controls instead of making every agent run a retrieval workflow.

Runtime gate

Mediate execution

Pair secret injection with command approval so sensitive tools remain visible when agents attempt to act.

How it works

Automic Vault protects the moment of use.

Save

Use av save KEY to store a secret outside the repo and away from normal file reads.

Inject

Use av inject +KEY /abs/tool so the selected executable receives the value only for that run.

Contain

Use av contain to route agent tool execution through a mediated path with approval prompts.
