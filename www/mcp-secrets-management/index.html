MCP secrets management

MCP servers make tools easier for agents to use. Automic Vault keeps the credential boundary explicit: tools can receive approved access, but the model does not need to see the secret value.

MCP risk

Tool access is not the same as secret access.

An MCP server may need credentials to query services, update issues, read cloud state, or publish artifacts. That does not mean the agent should receive raw tokens as prompt context or environment it can inspect.

Server config

Avoid plaintext MCP credentials

Do not make local JSON, dotenv, or shell profiles the default secret store for agent tools.

Tool execution

Approve the action path

Route sensitive tool commands through approval gates so humans see what will run.

Scoped values

Inject only named secrets

Give a server or command the exact values it needs for that invocation.

Audit shape

Think in capabilities

The useful record is which tool got which capability for which run.

Pattern

Keep MCP servers useful and constrained.

Local secret

Save API tokens with av save instead of writing them into MCP server config.

Server launch

Start the sensitive server or helper through av inject so only it receives the required keys.

Agent run

Use av contain for sessions where the agent can call tools that mutate real systems.
