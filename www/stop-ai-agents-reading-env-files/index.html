Dotenv protection for agent runs

Stop AI agents from reading your .env files

A dotenv file is a shortcut for local development, but an AI agent with filesystem access can read it as easily as your app can. Automic Vault moves secrets out of the file and into approved runtime injection.

The failure mode

Dotenv makes secrets ambient.

.env works because every tool in the project can find the same values. That same convenience gives agents, malware, dependency scripts, and accidental shell commands a direct path to credentials.

Readable by design

cat .env should not be a credential path

Agents can inspect files while planning, debugging, or satisfying a broad request.

Easy to spread

One paste can leak every key

Once a model sees a dotenv file, the secret can appear in logs, tool calls, summaries, and patches.

Poor scope

All keys arrive together

A deploy command usually needs fewer secrets than the full project environment contains.

Better boundary

Inject only what runs

Automic Vault gives the target executable named keys at runtime instead of leaving them in a repo file.

Practical migration

Keep developer ergonomics without plaintext.

Before

dotenv, python-dotenv, and dotenv npm all load values from project-readable files.

After

av save stores the sensitive value once, then av inject supplies it to an approved command.

Agent run

av contain keeps host tool execution visible when a coding agent attempts to use the command.
