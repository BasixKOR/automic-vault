Human approval for agent commands

AI agent approval gates

Automic Vault puts approval gates in the tools and execution paths agents depend on. If an agent tries to reveal a token, publish a package, or run a sensitive CLI action, the decision happens below the agent.

Run agents through contain › Agent PAM ›

Right layer

Agent-side controls are not enough.

Built-in allowlists and prompts help, but they live inside the agent. If a session is misconfigured, compromised, or too broad, those controls can fail at the same layer that is making the plan.

Tool layer

Gate the executable

Automic Vault mediates host tool execution rather than trusting every agent policy setting.

Secret layer

Gate credential use

Secrets are injected only when an approved target path receives named keys.

Package layer

Keep tools stable

Root-owned package roots reduce accidental or malicious tool rewrites.

Human layer

Show a real decision

The approval prompt is about the action that will run, not a vague promise from the model.

Examples

Use gates where the blast radius changes.

Publish

An agent tries npm publish, twine upload, or another package release command.

Reveal

An agent tries to print tokens with commands such as gh auth token.

Cloud

An agent tries to run AWS commands that can inspect, mutate, or delete infrastructure.
