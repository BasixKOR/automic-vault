Case file: GitHub CLI

We aftermarket modded gh to securely seal its token in the macOS keychain. No other process can read it, print it or dump it. Explicit requests of the tool itself to dump a token are gated behind an Automic Vault approval prompt. Check out the patches.

Case file: AWS CLI

We adapted aws-cli so credentials stay behind Automic Vault instead of sitting in plaintext config files. Agents can invoke AWS capabilities, but credential export stays gated behind explicit approval.

/// why not just use…

The right tool is the one that fits the threat.

Homebrew

Great for installing software. Not designed to secure it.

brew install works exactly as before. The difference is what happens underneath — the package root is immutable, and nothing else can touch it.

1Password

Great for protecting secrets at rest. Not designed to control how they're used.

Automic Vault ensures only the right tool gets a secret — and only at the moment it needs it. No other process can read what gh holds. There's no retrieve step. No plaintext moment.

Keycard

Great for governing agents at enterprise scale. Not designed for the individual developer.

SDKs, infrastructure, a security team, a budget. Automic Vault is for the developer who wants control today, locally, without standing up a platform.
