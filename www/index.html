/// Secrets

We patch away plain text secrets

Open Source was built assuming you would not let another intelligence have filesystem access. Plain text secrets are (sadly) the norm.

Automic Vault patches packages so the only thing getting those secrets is the tool itself.

Agents and malware can suck it.

Before $ cat ~/.aws/credentials [default]
aws_access_key_id = AKIAIOSFODNN7EXAMPLE
aws_secret_access_key = wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY

Agents, malware—any process that can read the file can snatch your credentials.

After $ cat ~/.aws/credentials file not found

Automic Vault patches critical tools to store secrets encrypted in the keychain.

/// Approval Gates

We patch gates into the tools themselves

Agents come with increasingly comprehensive execution controls. But it's the wrong layer.

  • Configuration is painful and error-prone.
  • Defaults tend to be all or nothing—neither of which are fun or safe.
  • If agents are compromised the gates are compromised too.

Automic Vault patches the tools themselves.

  • The gates cannot be bypassed.
  • They are applied as needed, not before the commands run.
  • Security that is tedious gets turned off. We don’t want you to turn it off. We're intimiately familiar with the corpus of Open Source. We put the gates in *tastefully*.

/// Immutable Installs

Agents can’t modify their tools or themselves

Approval gates and secure secrets only hold if the underlying toolchain cannot drift behind your back. Automic Vault installs packages as root.

01

Each tool gets a sealed package root. Agents can run what was installed, but they cannot rewrite binaries, patch the package in place, or smuggle in a replacement.

02

Dependencies stay transitive, not ambient. An install only sees the stack it actually depends on instead of reaching sideways into unrelated packages.

Case file: GitHub CLI

We patched gh to:

  • Securely seal its token in the macOS keychain such that the only tool that can access it is itself.
  • Guard sensitive actions behind human approval gates.

Check out the patches.

Case file: AWS CLI

We patched aws-cli so credentials stay behind Automic Vault instead of sitting in plaintext config files. Agents can invoke AWS capabilities, but credential export stays gated behind explicit approval.

/// comparing Automic Vault

The right tool is the one that fits the threat.

Automic Vault is a package manager, secrets manager and execution control manager combined. This unlocks new levels of security and control never before seen.

Homebrew

Package Manager

We install Homebrew packages the same as brew. The difference is what happens underneath — the package root is immutable and installations only get access to their transitive stack.

With Automic Vault agents can’t modify their stack or *themselves*.

1Password

Secrets Manager

Automic Vault ensures only the right tool gets a secret — and only at the moment it needs it. No other process can read what gh holds. There's no retrieve step. No plaintext moment.

The 1Password cli, op, has controls but they are not granular at the installation layer.

Built-in Execution Controls

Execution Control

Claude Code, Cursor, Codex — they all ship with some execution controls. But those controls live inside the agent. Automic Vault lives at the layer beneath it — the tools, the secrets, the packages the agent runs on.

If the agent is compromised, its built-in controls are compromised too. Ours aren't.
